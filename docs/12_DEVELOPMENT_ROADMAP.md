# 12 — 开发路线图与依赖关系

## 1. 执行策略
从空仓库开始，先建立可运行工程，再做垂直切片。每阶段结束必须有可演示成果、自动测试、验收报告和 Git commit。禁止先堆完整后端再最后做 UI；每个里程碑至少有可操作界面或 API demo。

## 2. 阶段顺序
| 阶段 | 范围 | 优先级 | 前置 |
|---|---|---|---|
| S0 | 仓库规范、monorepo、CI、Docker 基础 | P0 | 无 |
| S1 | FastAPI、Next.js、Postgres、Redis、认证、项目 CRUD | P0 | S0 |
| S2 | 文件上传、对象存储、异步 Job、SSE | P0 | S1 |
| S3 | PDF 解析、页面预览、来源定位、人工校对 | P0 | S2 |
| S4 | 知识点/题目库、检索和来源引用 | P0 | S3 |
| S5 | 教学规划、大纲审批、LangGraph 生成 section | P0 | S4 |
| S6 | ChemSpec、Validator、2D Renderer、3D PoC | P0 | S5 |
| S7 | Review、盲审、质量门禁、有限修复 | P0 | S6 |
| S8 | 编辑器、版本管理、HTML/PDF 导出 | P0 | S7 |
| S9 | 端到端、性能、安全、部署和教师试用 | P0 | S8 |
| S10 | 模板配置、对话助手、扩展格式 | P1 | S9 |

## 3. 里程碑验收
M0：开发环境一键启动、CI 通过。
M1：教师登录、创建项目、资源隔离。
M2：上传 PDF，任务异步解析，查看页面和原文定位。
M3：建立知识点和题目，检索结果可回到原 PDF 页。
M4：大纲生成、教师修改和批准；逐节生成内容。
M5：ChemSpec 可表达目标结构，校验器能识别固定错误 fixture，2D 图可渲染。
M6：审核结果和证据可查看，硬错误阻断批准。
M7：可编辑讲义、版本回滚、PDF 稳定导出。
M8：教师用真实授权资料完成至少一份讲义，记录质量和耗时反馈。

## 4. 依赖约束
- S3 先于 S4：知识抽取依赖可靠来源定位。
- S4 先于 S5：规划依赖知识点/题目/来源。
- S5 先于 S6：结构规格来自内容生成，但 ChemSpec schema 可在 S5 早期并行设计。
- S6 先于 S7：审核依赖确定性校验和可见图形。
- S7 先于正式导出：不合格内容不得标记 approved。
- S8 前端编辑器可提前做基础壳，但完整编辑能力需内容 schema 稳定。

## 5. 并行工作
可并行：前端静态页面与后端 API contract；解析器 PoC 与 UI 信息架构；ChemSpec schema 设计与教学内容 schema 设计。
不可并行：多个 Agent 同时修改同一数据库模型/API schema；在接口未冻结前同时实现上下游。

## 6. 估算
不提供虚假工期承诺。每个任务先由 Agent 报告复杂度、依赖、未知项和风险，负责人确认后执行。工期按真实 PoC 结果调整。
